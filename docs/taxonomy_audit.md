# Taxonomy Audit — CFPB Product / Issue Label Fragmentation

## Why this exists

```
Raw CFPB Labels
       |
  Taxonomy Audit
       |
 Canonical Labels
       |
   ML Dataset
```

The CFPB has revised its complaint-form Product and Issue taxonomy
several times since 2012. Each revision renamed and/or consolidated
some values, but the historical data keeps every era's wording. A
classifier trained directly on raw labels therefore sees the *same*
real-world category as 2-3 separate classes, which fragments its
training signal and disproportionately damages Macro F1 (macro
averaging weights every class equally, and fragmented classes look
artificially rare).

This audit does not delete or overwrite any raw label. It defines a
`raw label -> canonical label` mapping (`src/taxonomy.py`) that sits
between the raw CFPB data and the ML dataset, while the raw label is
always kept alongside the canonical one for full traceability.

## How the mapping was built (and its limitation)

This project does not currently have access to either the raw CFPB CSV
(`data/raw/complaints.csv`, ~8-9 GB) or network egress to download it,
so the mapping below was **not** built by mining raw label
co-occurrence or frequency directly. It was built from two sources
combined:

1. **Publicly documented CFPB taxonomy history.** The CFPB has
   published (and consumer-complaint researchers have documented)
   several Product/Issue renames and consolidations over the years —
   e.g. `Credit reporting` -> `Credit reporting, credit repair
   services, or other personal consumer reports` -> `Credit reporting
   or other personal consumer reports`.
2. **The raw labels this project's own classifiers were actually
   trained and evaluated on.** Every raw string in the mapping is a
   label that appears in `models/nlp/product_classifier_metrics.txt`
   or `models/nlp/issue_classifier_metrics.txt` — i.e. it is grounded
   in this project's real data, not a generic/textbook list.

Every merge carries an explicit confidence flag:

- **high** — near-certain rename/consolidation of the same concept
  (only wording or punctuation changed).
- **medium** — very likely the same concept, but should be confirmed
  against real label co-occurrence/frequency once the raw dataset is
  available.

Unknown/unseen labels are never dropped or forced into an existing
group — they simply become their own canonical category, so the
mapping degrades gracefully on data it hasn't seen.

**When the raw dataset becomes available**, run
`audit_dataframe()` in `src/taxonomy_audit.py` against the full
`Issue`/`Product` columns to validate the medium-confidence merges
with real frequency and (ideally) narrative-text similarity, rather
than label-wording similarity alone.

## Reading the results

- **Product**: 18 raw classes collapse to 11 canonical ones. The
  `Credit Reporting` group alone consolidates 13,168 test-set examples
  that were previously split three ways — including 172 examples
  stuck in the `Credit reporting` legacy label, too few on their own
  to ever be predicted reliably.
- **Issue**: 75 raw classes collapse to 63. The rare-class count
  (support < 50) drops from 37 to 28 — nine categories that were
  previously too data-starved to train on reliably now have enough
  combined support to be modeled properly. `Incorrect Information on
  Report` alone gains 114 examples that were fragmented into a
  same-meaning label with a different name.
- One group — `Consumer Loan (Legacy)` — is intentionally **not**
  merged into anything else. CFPB retired the `Consumer Loan` product
  around 2017 and redistributed its complaints across several newer,
  more specific products with no single clean replacement. Forcing a
  merge here would be a guess, not an audit finding, so it's kept as
  its own bucket and flagged for sub-issue-level disambiguation once
  the raw dataset is available.
- Similarly, `Getting a Loan or Lease` / `Getting the loan` is flagged
  **medium** confidence rather than high, specifically because
  "Getting the loan" is a narrower phrase and this merge should be
  double-checked once real narrative text is available.

## Where this is used

| Component | How it uses the taxonomy |
|---|---|
| `src/nlp_model_training.py` | Trains Product/Issue classifiers on the canonical label; the raw label is kept as `{column}_raw` and never deleted. |
| `src/nlp_predictor.py` | Applies the same canonical mapping to the **already-shipped** models at inference time, by summing predicted probability across raw classes that share a canonical label. This works today, without retraining. |
| `src/nlp_evaluation.py` | Reports Macro/Weighted F1, Top-K accuracy, and per-class detail on the canonical label set once models are retrained. |
